# Canvas Atelier 1.6.65

这是一次针对模型目录和 RelayMe 生图链路的可靠性修复。重点不是增加模型数量，而是确保当前供应商、连接检测和真实生成任务使用同一套可靠状态。

## 本次修复

### 模型目录不再串台

- 切换 Comfly 与 RelayMe 时，会立即清空上一供应商的模型目录，再加载当前供应商数据。
- RelayMe 加载期间或偶发失败时，不会继续显示 Comfly 的 495 个旧模型。
- RelayMe 目录继续按可用能力去重和过滤，当前账户应显示 7 个有效模型：3 个生图、3 个视频、1 个对话。

### 修复“检测连接成功，但生成仍失败”

- 根因是 Comfly 与 RelayMe 共用了同一份加密任务映射文件，但两者使用不同密钥，RelayMe 无法解密 Comfly 写入的记录。
- 1.6.65 为 RelayMe 使用独立的安全任务映射目录，同时保留既有 Comfly 任务记录，避免迁移时破坏旧任务。
- 连接检测成功后，RelayMe 现在可以正常建立生成任务，不再立即报 `Provider task mapping is unavailable`。

### 错误提示更准确

- 若本地任务状态仍发生异常，界面会明确提示“本地模型任务状态不可用”，并给出重启或重新登录当前供应商的处理建议。
- 不再把这一类本地状态故障笼统归因于 API 密钥或模型配置。

## 更新说明

打开“设置 → 同步 → 高级故障排查 → 检查更新”，下载完成后由你决定何时重启安装。应用不会静默安装更新。

建议安装后重新打开“API 与模型”，确认 RelayMe 显示 7 个有效模型，再用 Nano Banana Pro 发起一次生图任务。
