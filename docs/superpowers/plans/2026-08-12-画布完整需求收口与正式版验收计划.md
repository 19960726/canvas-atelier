# 画布完整需求收口与正式版验收实施计划

> **执行要求：** 按测试驱动逐项实施；每一阶段结束必须提交对应自动化测试、实际界面截图或安装版运行证据。没有证据的项目只能标记为“待验证”，不能标记为完成。

**目标：** 把此前分散提出的画布、节点、项目保存、API、模型、Agent、知识库、MCP、历史记录、Photoshop 与安装包需求统一收口，并交付可以覆盖安装、自动恢复工作状态的正式桌面版。

**架构：** Electron 主进程负责固定用户数据目录、安全密钥、项目仓库、最近项目、缓存目录和 MCP 生命周期；React/Zustand 负责画布、节点和设置界面状态；Provider Registry 把 Comfly 与 RelayMe 的同名模型去重显示但保留各自路由；所有图片、视频、反推和对话任务使用统一任务状态机与历史记录。

**技术栈：** Electron 43、React 19、TypeScript、Zustand、React Flow、Vitest、Playwright、electron-builder/NSIS。

## 全局约束

- 保留当前工作树中已有修改，不重置、不覆盖无关文件。
- API 密钥只能保存在 Electron `safeStorage` 加密凭据库，不写入项目 JSON、日志、截图或前端持久化状态。
- 覆盖安装、版本升级和普通重装不得要求用户重新填写仍有效的密钥。
- 当前项目自动保存；点击“保存项目”更新当前项目，不重复创建项目和缓存条目。
- 只有“新建项目”创建新的空白画布；下次启动自动恢复退出前最后使用的画布。
- 项目列表不显示画布缩略图，只显示名称、节点/连线数量、更新时间和操作。
- 图片、视频、素材槽、生成记录都必须按真实结果数量显示，不伪造占位结果。
- 所有按钮文字、图标、数字水平和垂直居中；深色、浅色主题几何尺寸一致。
- 节点模型选择器只显示模型名称，不显示 Comfly、RelayMe 等网站名称。
- 相同模型名称只显示一次，但内部保留对应供应商与密钥路由。
- 所有外部付费生成任务必须显示提交中、运行中、失败和取消状态，不能点击后无反应。
