# Codex Agent 对话工作台设计

## 目标

在 Canvas Atelier 右侧 Agent 面板中实现与用户参考图一致的对话信息架构，并保持 Canvas Atelier 自己的浅色、青绿色、圆角和间距体系。对话任务按项目画布隔离保存，模型选择来自当前完整供应商目录，画布操作继续通过现有工作区 API、确认边界和 CanvasForge MCP 执行。

## 预改复盘

- 当前 `SkillChatWorkbench` 只在 `sessionStorage` 中保存每个项目的一份消息数组；顶部“新任务”下拉框是静态选项，“新建任务”实际仅清空当前数组，因此没有真正的任务列表、切换或持久化。
- Codex 结构样式已写入 `app.css` 约 2132 行，但同文件约 4500 行之后仍有旧 `.agent-panel .skill-chat-workbench*` 规则。后置规则重新设置网格、空状态、建议卡片和 166px 编辑器，导致新界面被级联覆盖。
- Agent 已能获得未经过节点目录压缩的完整聊天 profile，Codex 同名不同 route 也已保留；但模式和推理强度只存在于临时 React state，尚未随任务保存。推理强度应优先选择同一 Codex 模型族的 low/medium/high route，而不是向不支持该字段的供应商伪造参数。
- `ConnectedAgentMediaSlots` 的数据重排支持任意索引，但终端 CSS 仍让重排覆盖层与横向滚动层竞争指针命中；Chromium 还需要显式隐藏 WebKit 滚动条，否则 Windows 会显示箭头并压缩图槽。
- 工作区非常脏。所有修改必须局限于本规格列出的文件，不重置、不清理、不覆盖其他未提交改动。

## 参考实现中可借鉴的逻辑

对本机 `桥豆麻衣酱_V.3.5.0-08-12.exe` 只做静态分析，不执行程序。可确认其对话架构分为：会话索引、按会话排序的消息 payload，以及本地画布桥接动作。Canvas Atelier 借鉴这些职责边界，但不复制其私有接口、资源、品牌或网络端点。

## 信息架构

### 顶部任务栏

- 标题为 `Codex Agent`，旁边显示 `画布接入` 标签。
- 显示绿色圆点与 `运行就绪`；没有可用聊天模型时显示 `未配置模型`。
- 任务选择器列出当前项目的所有会话，按最近更新时间倒序排列。
- `+` 创建新任务并立即切换；不会删除旧任务。

### 消息区

- 空任务居中显示机器人标记、`Codex 已接入当前画布` 和 CanvasForge MCP 说明。
- 有消息时保持现有用户/助手消息、来源、错误和画布动作确认卡片。
- 切换任务时，消息、模式、模型、推理强度、知识库和项目记忆一并恢复。

### 输入区

- 大圆角输入框固定在面板底部。
- 左侧保留素材导入。
- 模式为 `对话 / 原智能 / Codex`；Codex 模式只展示 Codex profiles，其他模式展示可用聊天 profiles。
- 模型按钮打开现有模型面板。
- 推理强度为 `快 / 中 / 深`。当同一 Codex 模型族存在 route 变体时切换对应 route；不存在时只保存偏好，不伪造供应商参数。
- 发送按钮保持圆形；请求发送期间禁用重复提交，并继续使用现有超时与错误恢复逻辑。

## 会话数据模型

新增独立存储模块，避免继续膨胀 UI 组件：

```ts
export type AgentConversationMode = 'chat' | 'original' | 'codex';
export type AgentReasoningEffort = 'low' | 'medium' | 'high';

export interface StoredAgentConversation {
  readonly id: string;
  readonly title: string;
  readonly mode: AgentConversationMode;
  readonly reasoningEffort: AgentReasoningEffort;
  readonly modelRoute?: string;
  readonly knowledgeBaseIds: readonly string[];
  readonly projectMemoryIds: readonly string[];
  readonly messages: readonly StoredAgentMessage[];
  readonly createdAt: number;
  readonly updatedAt: number;
}

export interface StoredAgentConversationCollection {
  readonly version: 2;
  readonly activeConversationId: string;
  readonly conversations: readonly StoredAgentConversation[];
}
```

- 存储键包含编码后的 `projectId`，不同项目不会互相读取。
- 使用 `localStorage` 提供关闭软件后的恢复；读取旧版 `sessionStorage` 单会话数据并迁移为一个 v2 任务。
- 数据解析必须过滤非法对象、非法角色和空 ID；存储失败不能阻断对话。
- 新任务标题初始为 `新任务`，第一条用户消息后用前 18 个可见字符生成标题。

## 图槽交互

- 所有槽位保持统一 40px 正方形和稳定序号。
- 整个缩略图仍是拖拽手柄；左右微调按钮默认不可命中，只在 hover/focus 时显示并启用。
- 横向溢出允许滚动，但隐藏 Firefox 与 Chromium/WebKit 原生滚动条。
- 槽位 5 以后必须与槽位 1 至 4 使用同一重排路径，不增加特殊分支。

## 引用图片视觉分析协议

Agent 请求必须把引用图片的顺序和语义一起送到模型入口，不能只传二进制图片。每个引用包含 `assetId`、显示标签和稳定的 `@图片N` 标记，并与 `referenceAssetIds` 一一对齐。

当满足以下任一条件时启用结构化视觉分析：

- `原智能` 模式包含至少一张引用图片；
- `Codex` 模式包含至少一张引用图片，并且任务涉及分析、复刻、提示词、生图、视频或工作流；
- 普通`对话`明确要求分析图片、反推、复刻或生成提示词。

模型必须仅根据图片中真实可见内容工作，不把猜测写成事实，并按以下合同输出：

1. 识别真实可见的主体、环境、材质、光线、镜头和景深。
2. 分析场景结构：前景、中景、背景、主体位置、空间层次、遮挡关系，以及桌面、墙面、置物架等空间连接。
3. 分析构图：视觉中心、留白、安全区、画面比例、水平线、引导线、主体占比和裁切方式。
4. 分析空间感：机位高度、镜头压缩感、前后景距离、景深衰减、透视关系和纵深来源。
5. 为每个 `@图片N` 明确职责：产品、构图、道具、服装、灯光、材质或其他可验证角色；不能识别时标记为不确定。
6. 分别列出继承、替换、禁止照搬的内容，禁止默认复制参考图中的品牌、文字、水印、人物身份或受保护标识。
7. 输出中文提示词、英文提示词、负面约束和可执行清单。执行清单使用引用顺序，供后续创建节点、连接素材和运行生成时复用。

该协议在 desktop-core 的 Skill Chat 系统提示词层构建，UI 只提交模式、是否启用分析以及引用映射。这样所有供应商 route 使用同一合同，且不会因为界面改版丢失规则。

## 反推完成后的工作流确认

- 当带引用图片的结构化反推成功返回后，Agent 在同一条助手消息下显示：`是否基于本次反推生成工作流？`
- 提供三个明确选择：`生成工作流`、`继续调整`、`暂不生成`。
- `继续调整`只把修改要求放回输入区；`暂不生成`只关闭询问，两者都不能修改画布。
- `生成工作流`把本次反推文本、按顺序的 `@图片N` 与素材 ID 交给现有 `draftAgentPlan`，生成可预览方案；仍须用户在画布方案卡片再次确认后，才允许创建节点、连线或运行模型。
- 该询问只绑定产生它的助手消息和当前任务；切换任务后不会串到另一段会话，也不会把旧反推误当作最新结果。

## 样式约束

- 最终 Agent 规则放在 `app.css` 的真实末端，并使用 `.workspace--ui-gate .agent-panel--skill-chat` 作用域，覆盖旧实验规则而不影响节点卡片。
- 不启动 GUI 做日常验证。优先使用 DOM 测试和静态级联断言；只有安装包验收时才使用双环境变量控制的隐藏 QA。
- 不改变现有节点按钮统一高度合同。

## 错误处理

- 无可用模型：模型按钮显示 `未配置模型`，发送按钮禁用。
- 存储损坏：回退到一个空任务，不抛出渲染错误。
- 请求失败：保留当前任务、用户输入恢复和既有错误提示。
- 画布命令：继续要求现有确认步骤，不因 Codex 模式自动执行。

## 验收标准

1. 同一项目可创建、切换至少三个任务，消息与选择项互不串线；重新挂载后恢复。
2. 不同项目使用相同任务名称时仍完全隔离。
3. 旧单会话存储能迁移，旧消息不丢失。
4. Codex 模式展示全部唯一 Codex route；切换快/中/深时选择相应变体（存在时）。
5. 空状态、顶部任务栏和底部输入区与参考图信息架构一致，最终 CSS 不再被后置旧规则覆盖。
6. 九个图槽均可拖动换位，左右按钮不再常驻遮挡，Windows 不显示滚动条箭头。
7. 现有知识库、素材引用、画布动作确认、发送失败恢复和 Backspace 防护测试保持通过。
8. 结构化视觉分析请求包含全部七项规则和按顺序的 `@图片N` 映射；无图片的普通聊天不被强制套用长格式。
9. 复制/粘贴图片到画布、显式/快捷键保存、右键图片操作、导入 Photoshop、按钮统一高度、完整图片预览和反推链路通过相关现有回归。
10. 通过聚焦测试、相关宽套件、类型检查、生产构建后才允许生成新安装包；安装过程不自动启动软件。
