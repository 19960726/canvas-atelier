## 1.1 本轮新增稳定性要求

本轮用户补充的截图和运行问题必须作为同一验收范围处理：

- 保存失败、保存超时、版本冲突或桌面持久化不可用时，画布不能被锁死在无法操作或无法退出的状态。保存失败必须保留当前编辑内容，提供重试；关闭窗口时必须等待保存结果，失败或超时必须给出“取消退出 / 重试保存 / 明确放弃未保存更改并退出”的可操作选择。不得通过静默 `app.quit()`、隐藏错误提示或直接丢弃 draft 解决。
- 保存过的项目必须在关闭后重新打开，节点位置、连线、文本、图片、视频、Agent 引用和生成结果保持一致；保存失败只能影响本次未保存更改，不能破坏上一次成功保存的项目。
- 节点、图槽、引用胶囊和画布控件的拖动结束后不得被旧的持久化响应、启动 hydration、自动布局或 fitView 恢复到拖动前位置。用户拖动坐标必须优先于旧源快照，直到对应 commit 明确成功或失败并完成可见恢复。
- Agent 顶部任务选择、加号、新建任务和关闭按钮必须使用同一垂直基线；输入框需要足够的高度、内边距和可滚动空间，不能因底栏或错误提示挤压正文。
- 图片复制必须分别验证：发送图片消息中的“复制图片”写入系统剪贴板；视觉对话模式粘贴图片后创建受管引用；Codex 文本/MCP 模式拒绝媒体时错误必须精确、可操作且不能残留到切换后的视觉/创作模式。
- `@图片N` 引用必须保持 inline chip 和正文同一行，序列化不得额外插入换行；用户主动按 Enter 仍应保留换行语义。Agent 对话和节点编辑器使用同一 canonical mention model。
- 删除或替换 Figma 专用运行时代码时，保留运行时通用 React Flow/Canvas API、既有 wire protocol 和可迁移项目数据；不把“删除字符串”当作迁移完成，必须通过构建、功能和存量项目重开测试。

此前对话记录中的 Astra 缓存补回修复已经修改源码，测试记录为 Codex 服务 28/28、Renderer 聚焦 2/2、desktop-core 类型检查通过。这是该次源码验证记录，不能表述为安装版已包含修复。Sol、滑动条、完整目录同步与最终安装验收仍是计划任务。

## 4. 思考滑动条

用户补充的五张滑动条截图是本节的具体视觉验收依据。各图不是五种不同控件，而是同一控件的五个选中状态：

| 补充图 | 显示档位 | 请求参数 | 五档目录下位置 | 轨道表现 |
| --- | --- | --- | --- | --- |
| 1 | 轻度 | low | 0% | 灰轨、最左白色圆形滑块 |
| 2 | 中 | medium | 25% | 普通主题色填充四分之一 |
| 3 | 高 | high | 50% | 普通主题色填充一半 |
| 4 | 极高 | xhigh | 75% | 普通主题色填充四分之三 |
| 5 | Ultra | ultra | 100% | 蓝紫渐变满轨，紫色档位文字及闪电 |

适配关键词：352px 最大宽度、受 Agent 输入框宽度约束、22px 圆角、细边框、轻阴影、16px 内边距、18px 居中档位、13px 模型副标题、左侧闪电、右侧恢复默认、36px 胶囊轨道、40px 白色滑块、44px 操作区、等距离散圆点、静态细碎光点。普通档采用画布青绿色，Ultra 保留紫色。复用现有字体与 Lucide 图标；光点不做持续动画。截图附带的录音与播放按钮不属于本次思考控件功能。

输入框使用显示当前档位的小胶囊入口；点开后自动聚焦 slider。支持鼠标/触摸、方向键、Home/End；Escape 关闭并回焦入口。弹层与模型/知识库/生成偏好互斥。点击标题可进入模型选择；重置使用当前模型默认档位。浅色、深色及窄面板均须浏览器截图与命中测试。若目录另外声明 Max，它必须作为单独一档出现，位置按实际档位数量等距计算。

顺序为 Low/low、Medium/medium、High/high、Extra High/xhigh、Max/max、Ultra/ultra。每个模型只呈现其实际支持的子集；不要求所有模型都有全部六档。默认档位来自该模型目录。

补充截图的 Astra Extra High 必须发送 xhigh；原图 2 的 Sol Ultra 在目录确认支持时必须保留 ultra，不能统一迁移成 max。先前对话中“固定五档、Ultra 全部转 Max”的描述作废。

滑动条使用 range 的离散整数索引，显示值和实际 effort 一一对应。支持鼠标拖动、方向键、Home/End、恢复默认。模型切换后保留仍受支持的档位；不支持时切到新模型默认值并提示。选择写入当前会话，不串到其他任务、Provider 路线或生成偏好。

## 5.1 引用胶囊与输入流设计规范（本轮新增）

引用胶囊是“正文中的一个不可拆分 inline token”，不是独立的表单行，也不是横向图片栏。图片生成、视频生成、反推 Agent 和 Agent 对话都使用同一 `MediaMentionTextarea` canonical mention model；只有尺寸档位和外部引用栏可以不同。

### 尺寸契约

| 使用位置 | 胶囊高度 | 缩略图 | 最大宽度 | 说明 |
| --- | ---: | ---: | ---: | --- |
| Agent 对话输入框 | 28–30px | 20–22px | 220px | 贴合正文基线，保留足够上下呼吸间距 |
| 图片生成提示词 | 30–32px | 22–24px | 220px | 与中文正文同一行，不能撑满输入框 |
| 视频生成提示词 | 30–32px | 22–24px | 220px | 与图片生成共用尺寸；视频缩略图使用 `object-fit: contain` |
| 反推 Agent 任务框 | 30–32px | 22–24px | 240px | 允许较长名称省略，仍保持 inline |
| 已选素材引用栏 | 30–32px | 22–24px | 220px | 独立 flex rail，可换行或横向滚动；不属于正文流 |

所有档位统一使用 `box-sizing:border-box`、`display:inline-flex`、`vertical-align:middle`、`flex:0 0 auto`、`width:max-content`、`max-width` 和单行省略。缩略图、标签和图标不得拆成 block；胶囊之间只保留 4–6px 外间距。正文行高至少为胶囊高度的 1.45 倍，避免胶囊顶住上下边界。

### 输入位置与换行语义

- 编辑器外壳是可换行的 inline flow：`display:block`、`white-space:pre-wrap`、`overflow-wrap:anywhere`；编辑器内部禁止 `display:flex`、`display:grid` 或每个 token 的 block wrapper。
- 文本节点和胶囊必须作为同级直接子节点。空间足够时，`前文 @图片1 后文` 保持同一行；空间不足时只发生浏览器自然换行，不人为给胶囊前后插入换行。
- 序列化只保留用户真实输入的空格和 Enter。插入胶囊时最多补一个必要空格，不能对整段内容 `trim()` 或写入隐式 `\n`。
- 光标插入、连续两个引用、引用后继续输入、Backspace/Delete、撤销、中文输入法和混合文本/图片粘贴必须保持同一 canonical value。删除胶囊后不得留下不可见 block 节点。
- 长标签在胶囊内部省略；不得把整个提示词输入框扩成一行横向图片带。视频生成的参数控制栏与正文引用流保持垂直分区。

### 样式归属与级联规则

`MediaMentionTextarea` 的通用尺寸和 inline 行为只允许由一个共享 release contract 定义；Agent、图片生成、视频生成、反推 Agent 只能设置容器间距和尺寸档位变量，不能再次用 `!important` 改写 `display`、`white-space`、`width` 或胶囊内部结构。现有 `agent-workbench.css` 与历史 release 规则必须在实现阶段做一次级联审计，最终以文件末尾的单一契约为准，避免旧规则把胶囊变回单行 rail 或把输入框压扁。

### 复制图片与引用状态边界

“复制图片”是消息结果操作，不受 Codex 文本/MCP 输入能力开关影响。复制成功、剪贴板权限失败、资源无效和当前环境不支持必须分别显示明确状态；Codex 拒绝媒体输入时只阻止粘贴/发送，不得隐藏已经生成消息的复制按钮。视觉对话或创作 Agent 粘贴成功后，受管 assetId 必须进入同一 canonical mention list，并在正文位置渲染胶囊。

### 可访问性与响应式

胶囊支持键盘聚焦、Backspace/Delete 删除和悬停预览；缩略图有可读的 `alt` 或 aria-label。800、1024、1440px 三种面板宽度以及窄屏下，胶囊不得溢出容器；超过最大宽度时标签省略，多个素材在独立引用栏中滚动，不改变正文行高。

### 验收指标

1. 组件测试：canonical value、真实换行、任意光标插入、连续引用、删除/撤销和混合粘贴。
2. 浏览器测试：Agent、图片生成、视频生成、反推 Agent 四处分别输入 `前文 @图片1 后文`；空间足够时测量胶囊与两侧文字同一行，窄宽度时确认自然换行且无横向溢出。
3. 几何测试：读取实际 `getBoundingClientRect()` 和 computed style，核对四类输入框的高度、胶囊高度、缩略图尺寸、最大宽度和垂直基线。
4. 安装版回归：重新构建 Renderer、桌面包和安装目录后重复上述测试；只报告当前安装包指纹对应的结果。
- 素材节点可从卡片空白和预览区域选中、拖动；内部编辑、播放、槽位排序各自有事件边界。位移后不误触展开；保存回写保留 React Flow 测量，不出现节点隐藏或跳回。
