# 统一图槽、画布性能与 Agent 对话可靠性设计

日期：2026-08-08

## 目标

本轮只处理三个已确认范围：

1. 生图、视频、反推与 Agent 图槽统一显示清晰的 `1–20` 顺序编号，拖动换位后同步重编号。
2. 优化节点拖动、画布缩放/平移、框选以及大量节点/大量媒体时的流畅性。
3. 修复 Agent 对话无法正常发送消息和上传图片/视频的问题，同时保持当前 Figma 风格布局不变。

## 统一图槽规范

所有连接素材与 Agent 引用素材共用一个序号徽标规范：

- 徽标位于缩略图右上角，固定深色背景和高对比白色数字，不依赖缺失的主题变量。
- 支持 `1–20`；一位数和两位数都在徽标中水平、垂直居中。
- 编号来自当前有序素材数组的索引，不写入持久化数据。
- 拖动换位、左右移动、删除素材后立即按照新顺序重新编号。
- 图片和视频封面使用同一徽标结构；浅色和深色主题只改变外层令牌，不改变编号对比度。
- 空图槽不显示伪造序号；只有实际素材才占用编号。

## 画布性能方案 B

保留 React Flow，不重写为 Canvas/WebGL。优化分为三层。

### 交互更新层

- 视口变化继续通过 `requestAnimationFrame` 合并，同一帧只发布最后一个 viewport。
- 节点拖动状态在本地 draft 中更新，松开鼠标后批量提交位置；拖动期间不写持久化状态。
- 框选多节点只更新选择集合，不重新生成无关节点数据。
- 连线预览和鼠标移动不触发项目事务。

### 节点渲染层

- 稳定模块运行上下文、节点数据和事件回调的引用，避免每次交互重建全部 React Flow 节点。
- 对模块节点卡片使用按节点数据比较的 memo 边界，使未变化节点跳过渲染。
- 素材 ID 到图片/视频摘要的索引在工作区级别缓存，节点不再对全部素材重复 `find`。
- 视口裁剪保留可见节点、选中节点、拖动节点和连线端点；其他节点不挂载。
- MiniMap 和非关键装饰在持续交互时降频，交互结束后恢复。

### 媒体层

- 缩略图使用延迟加载和异步解码。
- 视频图槽只加载封面/元数据，不预加载完整视频内容。
- 图槽图片保持原比例 `contain`，不在拖动或缩放期间重复计算原始尺寸。
- 最多 20 个图槽只渲染当前节点实际拥有的素材，不创建隐藏的 20 个媒体元素。

## Agent 对话与上传可靠性

### 发送消息

- 发送前明确验证已选择可用聊天模型、消息不为空、桥接接口存在。
- 浏览器验收桥和桌面桥都必须实现同一 `chatSkill` 合约。
- 发送中只锁定当前请求；成功后展示用户消息和 Agent 回复，失败时保留输入内容并显示中文可重试错误。
- 没有配置聊天模型时给出明确中文提示，不允许按钮无反应。

### 上传图片与视频

- 浏览器模式使用真实文件选择器；桌面模式使用受控桌面导入桥。
- 支持点击添加、粘贴图片/视频两条路径。
- 导入成功后立即显示真实缩略图并添加 `@序号` 引用；失败时不插入空白引用。
- 图片与视频统一最多 20 个引用，并与图槽顺序编号一致。
- 普通文字模型仍可正常纯文本聊天；只有实际引用媒体时才要求视觉模型。

## 验证标准

### 自动测试

- 图槽在 1、9、10、20 个素材时显示正确编号。
- 拖动第 20 个素材到第 1 位后，全部编号重新排列且素材身份不变。
- 生图、视频、反推、Agent 使用同一编号 CSS 合约。
- Agent 纯文本发送、图片上传、视频粘贴、视觉模型引用和失败重试都有回归测试。
- TypeScript 类型检查通过。

### 浏览器与性能验收

- 浅色和深色分别截图检查图槽编号。
- 300 节点、500 连线、80 个媒体素材下测试拖动、框选、平移、缩放和连线预览。
- 每次拖动只在松开后提交一次位置事务。
- 交互长任务目标低于 100ms；若运行环境不支持该目标，必须输出真实测量值，不可伪报通过。
- 用户测试页面必须能实际发送 Agent 消息并上传图片，不能只验证按钮可点击。

## 非目标

- 不重写画布渲染引擎。
- 不修改已确认的 Agent 对话栏视觉布局。
- 不新增虚构的 Comfly 模型或声称未配置密钥的真实 API 已调用成功。
- 不清理或覆盖工作区中与本轮无关的用户修改。
