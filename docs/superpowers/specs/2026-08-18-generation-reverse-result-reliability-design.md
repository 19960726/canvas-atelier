# 生图参考图、结果写回与反推可靠性设计

日期：2026-08-18

## 背景

当前安装版能够连接供应商并提交任务，但存在四个相互关联的问题：

1. 生图任务保存了 `referenceAssetIds`，供应商请求却只发送模型、提示词和尺寸参数，引用图片没有进入模型。
2. 供应商已经成功生成并将图片写入项目资产目录，但资产写入会推进桌面项目 revision；renderer 随后使用旧 revision 写回源节点，可能发生冲突，造成历史记录有结果而生图节点仍为空。
3. 反推调用走普通语言请求的约 30 秒默认超时，早于画布允许的反推等待时间；部分模型即使返回 JSON，也可能用 Markdown 代码围栏包裹，当前严格 `JSON.parse` 会将其判为失败。
4. 模型路由可以拥有不同 ID 却被格式化成相同显示名；反推节点表单又叠加了固定高度、绝对定位和后置 CSS 覆盖，造成名称重复、文案重叠或按钮溢出。

这些问题不能通过加强提示词或只修历史记录解决。修复必须覆盖从画布引用、供应商请求、结果落盘、项目事务到节点展示的完整数据流。

## 已确认的用户语义

当生图节点引用两张图片时：

- `@1` 是场景底图，是构图、机位、光线和背景的权威来源。
- `@2` 是需要替换进场景的产品，是主体外观、比例、材质、颜色、Logo 和识别特征的权威来源。
- 只替换 `@1` 中的主体，不得重新设计场景，不得改变机位、构图、光线或背景，不得把两件产品混合、并排或重复生成。
- 引用顺序必须从画布连接顺序稳定传递到供应商请求，不能按资产 ID、节点 ID 或加载完成顺序重排。

## 目标

- 支持参考图的生图模型必须收到真实、有序的图片内容，而不只是资产 ID 或文字标签。
- 不支持参考图的模型必须在扣费前明确阻止任务，并提示用户更换模型，禁止静默忽略引用图。
- 供应商成功后，图片和视频结果必须写回对应源节点，并在重新打开项目后仍然显示。
- 只有节点结果持久化成功后，任务才可进入“成功”状态；写回失败必须显示具体错误并允许恢复。
- 反推请求不得在约 30 秒被普通请求超时提前终止，成功结果必须显示在现有旁侧结果区域并持久保存。
- 模型选择器中，同一供应商、同一能力分类、同一规范化显示名只显示一次。
- 反推节点的角色、任务、知识库、模型、状态和操作区在 1.6.38 UI 基线上无文字重叠、无按钮溢出。

## 不在本轮范围

- 不更换 1.6.38 的整体 UI 基线，不恢复旧版界面。
- 不修改供应商计费规则，不虚构供应商不支持的模型能力或参数。
- 不读取、记录或展示用户保存的 API 密钥。
- 自动测试不发起真实收费生图、视频或反推；最终收费链路由用户在安装版中主动验收。

## 方案比较

### 方案 A：端到端修复（采用）

在桌面主进程受管地读取参考素材，将有序图片传给供应商；供应商成功后对最新项目 revision 重放幂等结果事务；反推使用独立长超时和结构化结果解析；最后在 UI 层完成模型显示名去重和反推布局收口。

优点是同时修复“生成不符合要求”“结果消失”“反推空白”和“重复/重叠”的根因。缺点是涉及 provider、desktop persistence、job store 和 renderer 多层，需要较完整的回归测试。

### 方案 B：只增强提示词

把 `@1/@2` 语义加入文字提示词，但不传图片。改动小，却无法让模型看到真实产品和场景，不能满足需求。

### 方案 C：仅为一个模型硬编码图片参数

只对当前 Nano Banana 路由附加图片。短期可用，但切换模型后仍可能静默忽略引用素材，也不能解决结果写回与反推失败。

## 设计

### 1. 有序参考图解析与能力门禁

生图提交前，根据任务中的 `referenceAssetIds` 按原顺序调用受管素材读取接口。该接口只返回本项目内已验证的图片字节、媒体类型和资产标识，不向 renderer 暴露磁盘路径。

提交规则：

- 无引用图时保持现有文生图请求。
- 有引用图且路由支持参考图时，将图片编码为有序 data URL 数组，通过 Comfly 生图请求的 `image` 字段发送。
- Gemini 原生图片路由使用有序 `inlineData` parts，并在同一请求中发送约束文本。
- 任一引用不是本项目受管图片、读取失败或媒体类型不支持时，在提交前失败，不创建供应商计费任务。
- 路由没有参考图能力时返回明确的 `REFERENCE_IMAGE_UNSUPPORTED` 类错误，不降级为纯文字生图。

提交提示词会在用户原始提示词前附加稳定的引用合同，明确 `@1` 和 `@2` 的职责。该合同只约束参考图关系，不改写用户对最终画面的其他要求。

### 2. 生成结果事务与 revision 冲突恢复

供应商返回结果后，主进程先将媒体写入项目资产库。该操作可能推进项目 revision，因此 renderer 不能继续假设轮询前的 revision 仍有效。

结果物化使用专用的幂等事务：

1. 获取或重载最新持久项目和 revision。
2. 在最新源节点上重新构造结果更新，将图片写入 `data.config.resultAssetIds`，将视频写入 `data.config.videoResults`，每类最多保留 4 个。
3. 使用最新 revision 提交事务；若发生 revision 冲突，仅对这一幂等结果事务重新加载，最多再重试 2 次，不重放其他用户编辑。
4. 提交成功后再将任务标记为 `completed`。
5. 提交失败时任务保持可恢复状态并显示“结果已生成但写入节点失败”，不得显示成功徽标。

启动恢复继续扫描“供应商已成功且拥有资产 ID、源节点尚无结果”的任务，并用同一幂等事务补写。已有结果通过资产 ID 去重，避免重复插入。

### 3. 反推超时、解析和结果展示

反推调用使用独立的 provider 超时常量，不再继承普通聊天的 30 秒默认值：

- Gemini `generateContent` 和兼容视觉聊天都显式使用 120 秒 provider 超时。
- renderer 外层等待时间设为 135 秒，大于 120 秒 provider 超时，保留错误回传余量，避免两个计时器同时竞争。
- 超时、鉴权、模型不可用、媒体读取失败和返回格式错误映射为不同的脱敏中文错误，显示在反推节点内。

结果解析按以下顺序执行：

1. 接受原生 JSON 对象文本。
2. 接受单个 `json` 或普通 Markdown 代码围栏中的 JSON。
3. 对提取结果执行现有 `ReversePromptResult` schema 校验；缺少字段或包含无关文本仍视为无效响应。

成功后，完整反推文字结果必须写入源反推节点的 `data.config.reverseAgentResult`，并由现有旁侧结果面板展示，不新建第二套结果存储。项目重新打开时从源节点持久数据恢复，不依赖当前内存任务或历史抽屉。

### 4. 模型显示名最终去重

保留真实 `modelRoute` 作为提交身份，在 UI 投影阶段按以下键最终去重：

`provider + capability group + normalized display name`

规范化会统一空白、大小写和已知的供应商前后缀，但不合并实际名称不同的模型。发生冲突时按以下优先级保留路由：

1. 当前已配置且可调用。
2. 能力元数据完整。
3. 正式版本优先于 preview、minimal 或兼容别名。
4. 排序仍相同则稳定选择 model route 字典序靠前者。

去重只影响展示，不改变已保存项目中的真实路由；若旧项目保存的是被隐藏别名，加载时仍可解析并映射到保留项。

### 5. 反推节点布局

反推表单主体改为稳定的 grid/flex 文档流。角色、任务、知识库和模型区域使用内容约束和最小高度，不再依赖相互覆盖的绝对 `top` 值。底部状态和操作区保持 1.6.38 的尺寸、色彩和位置风格，但由单一最终级联规则控制。

布局必须满足：

- 输入文字自动换行，不能覆盖标签、下一字段或按钮。
- 节点缩放、深浅主题和常见窗口宽度下无水平溢出。
- 运行计时、成功/失败状态和错误正文占用固定区域，不推动连接点或按钮跳动。
- 旁侧反推结果出现后不遮挡源节点和连线。

## 错误处理

- 提交前错误不创建 provider task，不产生计费任务标识。
- provider 已成功但节点写回失败时，保留资产 ID 和恢复信息，历史记录与节点状态明确区分“已生成”和“已展示”。
- 所有错误日志与 UI 文案必须经过现有脱敏逻辑，不包含 token、data URL、base64、磁盘绝对路径或完整供应商响应。
- 用户重试会创建新的运行身份；结果写回恢复不会重复提交供应商任务。

## 测试与验收

### 单元与集成测试

- 两张引用图按 `@1/@2` 顺序进入 Comfly 请求，`image` 数组内容和顺序正确。
- Gemini 原生图片请求包含有序图片 parts 和引用合同。
- 不支持参考图的模型在供应商提交前失败。
- 主进程资产写入推进 revision 后，结果仍能写入原生图节点。
- 节点事务返回失败时，任务不能进入 `completed`；启动恢复能补写且不会重复结果。
- 反推模拟运行超过 30 秒时不会提前超时，120 秒边界和外层余量正确。
- 原生 JSON 与代码围栏 JSON 均可解析，畸形响应显示明确错误。
- 相同规范化显示名在同一能力列表只出现一次，旧路由仍能映射。

### 组件与 Playwright

- 生图成功后结果直接出现在源节点，刷新和重新打开后仍显示。
- 视频结果使用同一持久化规则。
- 反推成功后旁侧出现文字结果，刷新和重新打开后仍显示。
- 对角色、任务、知识库、模型、状态和按钮读取 bounding box，断言无交叠、无水平/垂直 overflow。
- 检查 1.6.38 深色与浅色主题，以及桌面常用窗口宽度。

### 安装版验收

自动测试、类型检查、构建和打包烟雾测试通过后生成新安装包。用户在安装版中使用自己的已保存密钥主动完成一次：

1. 两图产品替换生图。
2. 单图或视频反推。
3. 关闭并重新打开项目，确认生图、视频和反推结果仍存在。

在用户完成上述收费链路前，只能声明静态、自动化和安装运行路径通过，不能声明真实供应商生成已经验收。

## 完成标准

本轮只有在以下条件同时满足时才算完成：引用图真实进入供应商请求；生成结果稳定写回节点；反推不再被 30 秒超时截断且文字结果可见；重复模型名消失；反推 UI 无重叠；相关测试、类型检查、生产构建和安装包烟雾测试通过；最后由用户完成真实收费链路验收。
