# 反推结果选段发送至生图节点设计

## 目标

让所有当前反推模型先完成制作级视觉取证，再按“主体 → 动作 → 环境 → 摄影参数”生成可直接执行的中英文提示词；用户可以在结果中自由选择可用内容，并把所选文字发送到用户已经创建的图片生成节点。软件不得自动创建生成节点，也不得要求用户先复制、切换节点、手动粘贴。

## 当前问题与参考逻辑

当前画布把反推结果放在多个 `textarea` 中，并只提供“复制全部结果”。这造成三个问题：结果阅读层级混乱、用户难以跨区块选择内容、反推结果与生成节点之间没有可执行的数据通道。

参考软件的有效做法不是简单复制界面颜色，而是把 AI 输出作为一份连续、可滚动、可选择的结果文档，明确区分中文提示词、English Prompt、限制条件和分析内容。图片与视频生成节点则保持独立，由用户决定何时创建和使用。

参考案例还体现出一条重要的反推链路：先识别场景元素及其视觉职责，再把观察结果重组为模型可执行的提示词，并解释构图、光影、材质和氛围词为什么这样组织。当前专业反推请求虽然已经要求空间、材质、镜头、灯光、特效、流体和白底适配，但没有把最终提示词的内部结构与输出顺序约束得足够明确，模型可能返回信息很多但难以直接生图的长篇分析。

## 反推模型逻辑

所有支持 `reverse_prompt` 的当前模型路线共用同一份专业反推合同。Comfly、RelayMe 和后续兼容路线不得各自维护含义不同的提示词模板。

模型必须按照以下顺序思考和输出：

1. **可见证据取证：** 区分画面中实际可见、合理估计和无法确认的内容，不伪造焦距、EXIF、灯位或隐藏参数。
2. **场景元素与职责：** 对产品、人物、食物、家具、道具、背景、装饰、特效和流体逐项说明视觉职责、空间位置、比例、遮挡、纹理和应否继承。
3. **构图与摄影拆解：** 覆盖前中后景、视觉重心、留白、引导线、机位、估计焦距、透视、景深、焦点、光线、扫光、色温、反射和高级感来源。
4. **冲突与适配：** 多素材时给出主次、继承、冲突与裁决；所有模式都必须说明如何适配用户白底产品图并保护产品身份、Logo、包装文字、比例、轮廓和接触阴影。
5. **执行提示词重组：** 按 `Subject → Action → Environment → Camera and Composition → Lighting and Color → Materials and Textures → Effects or Fluids → Style and Quality` 的稳定结构生成提示词。没有证据的部分不得为了填满结构而编造。
6. **中英文输出：** 中文提示词与 English Prompt 必须表达同一方案，都能脱离分析正文独立复制使用；英文不能只是中文关键词直译。
7. **提示词逻辑说明：** 简要解释主体、动作、环境、构图光影、材质氛围和技术参数的组织理由，让用户知道哪些内容可以修改。
8. **负面约束与检查：** 单独输出不可照搬内容、产品保护约束和按制作顺序排列的执行检查清单。

单图、多图和视频继续使用现有模式分支：

- 单图必须深挖空间、比例、纹理、景深、焦点、焦距和透视。
- 多图必须逐张分析职责与纹理，再给出融合裁决，不能直接把多张图概括成一个风格。
- 视频必须按真实镜头边界拆分时间轴，分析运镜、速度曲线、稳定方式、扫光、特效、流体、转场和白底产品镜头适配。

最终结构化结果新增 `promptLogic`，包含主体、动作、环境、构图摄影、灯光色彩、材质纹理、特效流体、风格质量八个可独立选择的段落，以及一组简短的组织理由。原有 `positivePrompt`、`positivePromptZh` 和 `positivePromptEn` 继续保留，保证旧项目和现有界面兼容。

## 用户流程

1. 用户连接图片或视频素材并运行反推。
2. 反推完成后，结果以连续阅读文档展示，按语义分为场景元素职责、分析摘要、提示词逻辑、中文提示词、英文提示词、负向约束、制作级拆解和执行检查。
3. 用户可以拖选任意连续文字。选区有效时，在选区附近显示轻量操作条：
   - 复制
   - 发送到图片生成
4. 每个完整语义区块同时提供固定操作入口：
   - 复制本段
   - 发送本段到图片生成
5. 点击“发送到图片生成”后，弹出目标节点选择器。选择器仅列出当前画布中由用户创建的图片生成节点，不自动创建节点。
6. 目标节点显示名称、简短 ID 和现有提示词摘要，避免发送到错误节点。
7. 如果目标提示词为空，所选内容直接写入。
8. 如果目标提示词已有内容，弹出二次选择：
   - 追加：在现有提示词末尾插入空行后追加，默认选项。
   - 替换：用所选内容替换原提示词。
9. 写入成功后显示明确反馈，并在画布中短暂高亮目标节点；不自动运行生成，最终生成仍由用户确认参数后手动触发。

## 界面结构

### 反推结果阅读器

- 使用语义化 `article` 和 `section` 展示结果，不再把所有内容放入可编辑文本框。
- 正向提示词和负向约束仍允许通过显式“编辑”状态修改；默认状态优先阅读和选择。
- 保留当前暗色画布的颜色、边框、圆角和字体系统，不照搬参考软件品牌。
- 结果区域独立滚动，标题和操作入口保持可见，避免长内容把节点无限撑高。
- 中文提示词与英文提示词是一级区块，不能埋在“制作级拆解”的长文本中。
- 提示词逻辑按主体、动作、环境、摄影构图、灯光、材质、特效和风格质量分段，用户可以只发送其中需要的部分。

### 文字选择工具栏

- 仅当选区属于当前反推结果且去除空白后非空时显示。
- 鼠标、键盘选择均可触发；按 Escape、点击结果外部或选区清空后关闭。
- 不拦截浏览器原生复制快捷键，Ctrl+C 仍然可用。
- 操作完成后保留选区片刻并给出“已复制”或“已发送到节点”的状态反馈。

### 生图节点选择器

- 从当前项目节点实时读取 `image_generation` 节点。
- 空状态显示“请先在画布中新建图片生成节点”，只有关闭动作，不提供自动新建按钮。
- 多个节点时按照画布位置从上到下、从左到右排序，显示节点标签、短 ID、提示词摘要和是否为空。
- 支持键盘方向键、Enter 和 Escape。

## 数据与组件边界

### 结果内容模型

新增纯函数把 `ReversePromptResult` 映射成稳定的结果区块数组。每个区块包含：

- 稳定区块 ID
- 中文标题
- 内容类型
- 可复制的纯文本
- 是否允许编辑
- 是否允许发送到图片生成

专业拆解继续由现有结构化字段生成，不把整个结果预先拼成一个不可追踪的大字符串。

### 发送动作

在应用状态层增加一个持久化动作，输入包括：

- 来源反推节点 ID
- 目标图片生成节点 ID
- 选中文字
- 写入模式：`append` 或 `replace`

动作必须验证来源节点、目标节点和非空文字，并通过现有稳定项目事务写入目标节点的 `data.config.prompt`。成功后保持项目修订、自动保存和旧项目兼容逻辑一致。

UI 组件不得直接修改 Zustand 项目对象，也不得只更新图片生成组件的本地 `useState`，否则重开项目后内容会丢失。

### 图片生成节点同步

图片生成节点的本地提示词状态必须监听持久化配置变化。外部发送内容写入后，目标节点当前打开的提示词编辑器要立即更新；用户继续编辑时仍按现有生成流程提交。

## 错误与边界处理

- 没有图片生成节点：提示用户先创建，不创建替代节点。
- 目标节点在选择器打开期间被删除：阻止写入并刷新列表。
- 项目处于只读、恢复或保存冲突状态：复用现有持久化错误提示，不显示假成功。
- 选中文字仅为空白：不显示操作条。
- 选择了分析说明而不是提示词：允许发送，因为用户明确选择了内容。
- 超长选区：完整保留，不静默截断；由目标模型自己的限制在生成时处理。
- 重复点击：单次写入动作串行化，避免重复追加。

## 可访问性

- 所有区块操作有包含区块标题的可访问名称。
- 选区工具栏使用 `role="toolbar"`，状态反馈使用 `aria-live="polite"`。
- 目标节点选择器使用对话框语义，打开时聚焦第一个可用节点，关闭后焦点返回触发按钮或结果区块。
- 文本仍可通过键盘 Shift+方向键选择，不能只支持鼠标。

## 验证标准

### 单元与组件测试

- 结果结构正确分段，中文和英文提示词分别显示。
- 所有反推路线收到一致的专业合同，并明确要求场景职责、提示词结构和提示词逻辑说明。
- 单图、多图、视频三种请求分别保留既有深度分析要求。
- 任意文字选区能够打开工具栏并得到准确文本。
- 区块级复制发送完整区块文本。
- 没有生图节点时显示正确空状态且不创建节点。
- 多个生图节点按画布位置排序并显示摘要。
- 空节点直接写入；非空节点追加或替换行为正确。
- 外部写入后图片生成编辑器立即同步。
- 只读、恢复和并发保存失败时不显示成功。

### 真实桌面验收

1. 用户新建两个图片生成节点并给其中一个填写已有提示词。
2. 运行一次包含中文提示词、英文提示词和专业拆解的真实反推。
3. 拖选中文提示词中的部分内容，发送到空节点，确认内容立即出现且没有自动生成。
4. 发送完整 English Prompt 到非空节点，分别验证追加和替换。
5. 保存、关闭并重新打开隔离项目，确认两个目标节点的提示词仍然存在。
6. 截图对比参考软件和实现结果，重点核对阅读层级、滚动、选区操作条、目标节点选择器及长文本布局。

## 非目标

- 本阶段不自动创建图片或视频生成节点。
- 本阶段不在发送后自动执行生成。
- 本阶段不复制参考软件的品牌、窗口标题或完整视觉皮肤。
- 本阶段不修改已经修复的生图返图与历史记录逻辑。
- 本阶段不扩展到跨项目发送或全局剪贴板历史。
