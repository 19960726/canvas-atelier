# Novus Atelier Formal Canvas, History, and Cache Design

**Status:** Approved design baseline with 2026-07-18 scope amendments
**Scope:** Novus Atelier desktop canvas productization
**Compatibility:** Electron 22, Node 16, ES2019, React 18, TypeScript, Zustand, React Flow, Zod, and Lucide

## Product and legal boundary

Novus Atelier is an original bilingual desktop workbench for visual-generation workflows on an infinite canvas. It provides durable project work, controlled provider execution, explainable multimodal reverse analysis, generation history, cache controls, and approved knowledge growth. Reference software is observation-only: it may inform publicly visible workflow categories and capability semantics, but Novus must not unpack or decompile it, copy its source, UI, copy, branding, or trade dress, inspect credentials, reproduce hidden endpoints, or use private model identifiers.

Provider coverage is capability-based and uses only public or compatible provider inventories plus user-authorized credentials. It covers chat, vision, structured output, image generation, image edit/local redraw, pose, long-video understanding, controlled Comfy workflows, music generation, speech synthesis, and speech/audio analysis. Coverage means explicit module, routing, confirmation, execution, and error contracts; it never promises private-model parity or one-shot success.

The visual system supports `system`, `light`, and `dark` themes. `system` is the default and device-local overrides remain outside project data. The product mark and all UI are original; executable modules have distinct Lucide-based icon treatments.

## Canvas and module model

Domain owns strict schemas and stable internal identifiers. Desktop-core owns managed assets, provider execution, filesystem access, migrations, history, cache, and durable acknowledgements. The renderer receives narrow typed preload bridges only.

The catalog exposes exactly one user-visible `图片生成 / Image Generation` module. Its controls derive from the selected model profile: ordered references, mask, pose, dimensions or aspect ratio, quality, asynchronous execution, and provider-specific safe options. `image_generation_v1` and `image_generation_v2` remain serialized migration aliases only; catalog search, favorites, templates, and new project serialization use the unified module exclusively. Migration preserves ordered references, mask/pose inputs, route, configuration, job identity, and result identity.

The catalog exposes exactly one user-visible `Agent 反推 / Reverse Agent` node for image, text, line-art, and video analysis. It accepts ordered images, video ranges, text/task context, line-art, and approved knowledge or project-memory context. The legacy `video_analysis` and video-reverse types are migration aliases only, preserving their video ranges, results, and execution identity. The unified node detects static-scene, poster/KV, line-art/material, product-commercial, or video intent, while users can choose a compatible specialized Skill/version. A mixed-media run selects a profile that declares every required capability or presents an explicit composite plan; it never silently drops a modality.

Image generation, Reverse Agent, and result nodes remain freely draggable before and after execution. References are reorderable with thumbnails, ordinals, responsibilities, and video ranges. Pointer movement, pan, zoom, preview ordering, and transient drag state never persist; a drop makes one stable position/order transaction. Connections never force layout. Optional user-triggered layout is undoable, and locking is a reversible user action only. A confirmed execution snapshot freezes reference order for that run alone; the live graph remains editable and a subsequent run takes a new snapshot.

## Reverse Agent workbench and Skills

The right Agent dock has a dedicated `反推 / Reverse` tab, opened by the same workbench from any Reverse Agent node. A durable conversation binds project id and revision, selected node, ordered managed references, Skill id/version, approved knowledge snapshot, project-memory ids, prompt-library source, and frozen model route. Its original Novus fields appear in this order: model/provider route, compatibility mode, Skill/version, prompt-library source, `角色 / Role`, `任务需求 / Task Requirements`, managed references, and structured-output preview. Role selects a versioned Skill persona; Task Requirements accepts text plus stable-order connected Agent, text, image, video, and line-art nodes. The composer supports managed `@image` and `@video-range` mentions.

Progress is explicit: knowledge retrieval, evidence extraction, scene/effects decomposition, structured keyword generation, plan preview, confirmation, execution, and review. Follow-up changes are field-level diffs, such as fluid intensity, halo strength, subject scale, or copy-safe area; replace/continue behavior applies only to the current structured run and cannot invisibly append earlier keywords. Preview shows citations, grouped keywords, effect parameters, route and cost estimate, proposed canvas operations, and conflicts. Only explicit confirmation may create, update, or run canvas nodes or consume paid provider work.

Supported immutable Skills are Scene Keyword, Poster/KV, Line-art Material & Color, Product Commercial, Composition & Camera, Material & Lighting, Ecommerce Detail, and Effects. Effects cover fluid/splash, smoke/fog, particles, glow/halo, bloom/lens effects, caustics/refraction, motion blur, compositing, and post-processing. A Skill retrieves the current approved knowledge snapshot, project memory, and user-approved preferences before execution. Its structured output includes grouped keywords, positive prompt, negative constraints, spatial/layer relationships, material/light/effect parameters, evidence source, knowledge citations, and confidence. Poster/KV adds hierarchy, headline/copy-safe areas, product scale, focal point, background system, brand-color logic, and generation/edit recommendations. Line-art analysis adds region map or masks, palette, material/texture and roughness/metalness/reflection/transmission intent, lighting/shadow plan, and constraints; confirmed operations preserve geometry and proportions through managed control, mask, or edge inputs.

Each reverse run creates a new run identity, nonce, input fingerprint, knowledge version, Skill version, and frozen route. Starting another run marks previous output stale. Results with a mismatched identity, fingerprint, knowledge version, Skill version, or route are rejected. If changed inputs produce an identical normalized keyword set, the product sets `suspected_stale_output`, blocks downstream materialization, and offers explicit retry. A same-input rerun is valid. Static output covers scene, props, materials, lighting, composition, effects, and keywords; video output additionally covers shot timeline, camera movement, transitions, rhythm, keyframes, and effect evolution.

The Agent begins with a structured brief: output type, product/subject identity, aspect ratio, brand tone, copy-safe regions, ordered reference roles, and KEEP/CHANGE/NEVER requirements. Before paid work it shows the Skill/version, knowledge snapshot, route, structured output, canvas operations, conflicts, and estimated job count. Review scores subject accuracy, scene/props, composition, materials, lighting, effects, typography/copy-safe area, and brand consistency, with compare and targeted-redraw actions. Spending is bounded by the confirmed estimate and clear failure/cancellation states. Failed or rejected outcomes create local growth candidates with missed requirement, cause, correction, prevention rule, and verification evidence; only approved sanitized knowledge can synchronize. Raw media and private conversation text never synchronize.

## Prompt library, provider routing, and Photoshop handoff

The original editable Novus common-prompt library is available to generation modules and the Reverse Agent workbench. It contains capability-equivalent, non-proprietary templates for panorama, expression sheets, character/reference setup, cinematic color grading, storyboard grids, multi-camera grids, product three-view, portrait/face three-view, character sheets, plot/emotion boards, high-resolution enlargement, and storyboard scripts. Templates use stable ids and versions, Chinese-primary names, descriptions, compatible capabilities/models, parameter fields, previewable prompt diffs, and user/project scopes. Users may apply, duplicate, edit, favorite, organize, and approve custom templates into project knowledge. Import accepts user-owned or exported JSON, CSV, and text, validates it as Novus data, and never bundles or imports verbatim proprietary reference prompts. Applying or importing does not run a paid model before confirmation.

Dynamic provider profiles declare display name, provider, route/model id, input modalities, output type, structured-output support, Chinese capability, context/reference limits, async behavior, and available cost metadata. The route selector shows all matching profiles and shows incompatible profiles as unavailable with a reason. Recommendation is advisory; users can override only to a compatible route. Snapshots persist provider/model display identity and capability revision, never tokens or raw provider metadata. The renderer receives no tokens, raw task IDs, arbitrary URLs, filesystem access, process access, credential access, keychain access, or unrestricted network access. Controlled Comfy import rejects credentials, absolute paths, scripts, protected payloads, and unallowlisted nodes.

Managed raster image results offer `在 Photoshop 中打开 / Open in Photoshop`. The renderer provides only an opaque managed asset id. Desktop-core resolves it, validates and exports a confined temporary or project copy, then launches a user-selected Photoshop 2019+ compatible standard executable through a narrow bridge. It may detect registered standard installations and permits a validated user selection. It does not inspect license state, bypass activation, modify executables, or implement crack-specific behavior. PNG, JPEG, and WebP are supported first; layered PSD/document interchange needs a separately approved schema/plugin plan. Temporary copies are disposable cache and clean up reference-safely without deleting project or history originals.

## Persistence, history, storage, and security

Projects persist nodes, edges, configuration, managed assets, results, jobs, knowledge references, conversation history, and approved growth candidates only at stable transaction boundaries. `已保存` appears only after a durable main-process acknowledgement. Assets are managed files addressed by opaque IDs; project data does not embed Base64 originals. Disk-full, read-only, missing-asset, duplicate-open, corrupt-snapshot, and abnormal-exit paths are explicit and recoverable. The 300-node/500-edge acceptance scenario has real thumbnail shapes, long bilingual names, mixed execution states, the library, and Agent dock; no measured interaction stall exceeds 250 ms.

Generation history is authoritative rather than cache. It stores opaque IDs, timestamps, project label/id, provider/model display metadata, status, dimensions, file size, sanitized prompt summary/parameters, favorite state, availability, and project-reference count. It supports filtering, pagination, reuse-safe parameters, comparison, picker-based export, soft delete, restoration, and purge. Provider URLs, credentials, raw payloads, Base64, object URLs, and private paths neither persist in history metadata nor cross IPC.

History is protected; cache is disposable. Locations are user-configurable app-owned local directories and reject roots, project/install locations, network shares, symlinks, junctions, and other reparse points. Migration validates capacity, copies and hashes data, atomically switches configuration, retains the old location until success, and rolls back safely on failure. Cache includes thumbnails, previews, video frames, provider temporary downloads, failed/cancelled residue, rebuildable indexes, Chromium cache, and Photoshop handoff copies. Default quota is 10 GB and cleanup uses least-recently-used eligible entries older than 30 days or needed for quota. Preview discloses count, bytes, and protected references; cleanup never removes projects, history, favorites, knowledge, memory, or referenced assets.

Durable data, logs, snapshots, packages, and tests contain no API keys, authorization headers, Base64 originals, object URLs, raw provider payloads, or private absolute paths. Domain has no privileged desktop capability, desktop-core confines privileged work, and preload exposes narrow typed operations. Packaging, portable, and installer commands remain prohibited until functional, performance, security, Windows, Figma, and user-acceptance gates have evidence.

Release eligibility requires focused domain, desktop-core, renderer, migration, provider, reverse, prompt-library, Photoshop-handoff, history/cache, redaction, performance, and security tests; root typecheck/build; Playwright flows; secret/path scans; and `git diff --check`. Evidence includes light/dark 1366x768, 1440x900, and 1920x1080 views for empty canvas, module library, history, storage, unified image generation, Reverse Agent workbench, video timeline, prompt library, and 300/500 stress. Review verifies readable ports, no panel overlap, intended nonempty views, no placeholder art, and restrained desktop quality. Figma frames and physical Windows/user acceptance remain explicitly external gates until evidence exists.
