# Canvas Atelier Codex 与创作执行修复设计

日期：2026-09-08。用户已确认目标：Codex 模式说明并支持 API Key 登录；创作 Agent 按“分析、选方案、确认、独立执行、回报结果”的流程工作；方案与执行按钮需要更清晰；每次确认方案都创建自己的生成节点，不复用画布上已有的同类节点。

## 已确认根因

- Codex 通过本机 CLI 执行；CLI 官方支持 ChatGPT 与 API Key 两种认证，本机当前 `login status` 也确认使用 API Key。现有界面只写“上游调用时验证”，没有说明两种认证方式，通用错误又掩盖了具体调用阶段。
- `chooseCreativeOption` 会优先选择画布中已选的同类节点；画布只有一个同类节点时也会自动复用。因此一个新方案可以写进别人的旧节点。
- 方案按钮点击后只在消息流底部追加确认卡，原按钮没有选中状态，也不把确认卡带入视野，用户会认为没有响应。
- 节点错误选择器会显示任意历史失败任务，即使同一节点后来已有成功任务，因此可同时出现“成功”和“图片生成失败”。
- 本次真实生图的供应商结果与历史原图均已落盘，但项目结果事务在本地保存错误后没有完成回写；界面仍把供应商完成当作完整成功，形成任务、节点和历史三套状态不一致。

## 交互与数据流

创作 Agent 先返回一至三个结构化方案。用户点击方案后，方案卡显示“已选择”，确认卡自动进入视野并明确写出“将新建独立节点”。用户可在确认卡检查模型和参数，然后执行或取消。

确认执行始终生成新的节点 ID，创建新的图片或视频生成节点，并只连接本轮请求里的参考素材。旧节点不再作为创作方案执行目标。节点创建或保存失败时停止执行，并在 Agent 中显示保存、模型或参数对应的明确原因。

任务只有在结果素材存在且项目结果事务完成后才向 Agent 报告“结果已回写”。供应商已完成但项目回写失败时，保留可恢复的任务与历史素材，界面显示“结果已生成，但尚未回写画布”，不得显示完整成功。

Codex 标题与模型列表明确写“支持 ChatGPT / API Key 登录”。认证失败、模型不可用、MCP 连接失败和通用进程失败继续使用不同错误码，不展示密钥或底层私有路径。

## 视觉样式

方案使用独立卡片、标题、说明和底部操作区。“选择此方案”为描边主操作，选中后变为带勾的强调状态。确认卡使用清晰的步骤标题、模型行和操作栏；“确认并新建节点”为实心主按钮，“取消”为低强调按钮。所有按钮保持可见焦点、禁用态和至少 36px 的点击高度。

## 验证

- 组件回归先证明旧逻辑复用已有节点、按钮无选中反馈、确认卡不进入视野、历史失败覆盖后续成功状态。
- 修复后验证每次方案执行都带 `createNode=true` 与新节点 ID，旧节点 ID 不会传入执行函数；选择、取消、失败和完成文案符合真实状态。
- 运行 Agent、CanvasWorkspace、ModuleNodeCard、job-store 相关测试以及 Renderer 类型检查和生产构建。
- 生成新候选后使用隔离用户数据运行安装版创作流程；真实供应商调用只在用户主动执行时发生，自动验收使用零费用 fixture。
