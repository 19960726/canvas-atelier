# Canvas Atelier Installed Full Acceptance Repair Design

## Objective

修复并验证用户在已安装 `Canvas Atelier 1.6.90` 中确认的遗留问题：生图节点和视频节点控制栏出现双层边框与错误间距、反推节点显示 `反推anget`、保存或退出时仍出现保存失败，以及 Canvas Atelier 与旧 CanvasForge 的运行边界未完全隔离。新的正式安装包只有在真实安装运行路径完成全量验收后才允许交付。

## Confirmed Product Boundary

- `CanvasForge 1.8.2` 必须保留，并允许与 Canvas Atelier 同时运行。
- 两个产品不得共享画布项目、最近项目、恢复状态、单实例锁或可变 MCP 运行时文件。
- 不删除、不覆盖、不迁移用户的正式项目、素材或凭据。
- 正式用户数据只做脱敏只读诊断；所有修复验收使用隔离副本或新建隔离数据目录。
- 不以源码测试、DOM 尺寸或隐藏启动冒烟替代安装版视觉和保存验收。

## Confirmed Root Causes

1. `ModuleNodeCard.tsx` 在反推标题和工作台标签中直接硬编码 `反推anget`，绕过了领域模块目录中的正式名称 `Agent 反推`。
2. 媒体控制栏存在多轮历史 CSS 和更高特异性的展开态覆盖。旧验收只检查高度、坐标和控件数量，没有检查外层、picker 和 trigger 的边框拓扑，因此双层边框进入安装包。
3. `1.6.90` 的关闭修复只补充了异步保存后的错误码读取，没有证明实际用户项目的保存、锁恢复、关闭和重开链路。
4. 正式 Canvas Atelier 数据中至少有一个项目保留 `project.lock` 且 `clean-close.json` 为 `clean:false`。它必须被分类为真实并发写入或陈旧锁，不能笼统处理为保存失败。
5. Canvas Atelier 的稳定用户数据目录已经独立，但 MCP 运行时仍写入 `%APPDATA%\\CanvasForge\\mcp\\runtime-modern-v1.json`。当两个产品同时运行时，这一可变文件可能互相覆盖。

## Repair Architecture

### 1. Canonical Node Identity

节点标题、工作台标签和可访问名称统一从 `packages/domain/src/canvas-module.ts` 的模块定义读取。Renderer 不再为正式模块名称维护第二份硬编码文案。回归测试遍历正式模块目录，确认卡片标题、模块库名称和工作台标签一致，并禁止 `anget` 等错误文本进入产物。

### 2. Single-Layer Media Control Rail

生图和视频节点继续使用现有底部控制栏位置，但样式职责被明确分层：

- rail 只负责定位、背景、内边距和整体轮廓；
- picker wrapper 只负责布局，不画边框、不画第二层背景；
- visible trigger/select 是唯一有边框的交互表面；
- 隐藏的原生 select 只保留可访问语义和状态同步，不参与布局、不接收指针、不产生可见边框；
- 同一展开态只有一份终端规则，旧的相互冲突规则被删除或降为不生效的基础规则，而不是继续在文件末尾叠加补丁。

生图栏保持模型、比例、清晰度、数量、生成五个参与者。视频栏按当前产品能力保持模型、模式、参数、时长、生成五个参与者。两者在支持的节点宽度和缩放级别下保持单行、同基线、不越界。

### 3. Durable Save And Recovery State Machine

保存结果必须保留可诊断分类：`saving`、`saved`、`read_only`、`revision_conflict`、`concurrent_writer`、`recovery_required`、`disk_write_failed`、`timeout`。UI 显示可执行的恢复动作，不把所有错误折叠成“保存失败”。

打开项目时检查锁拥有者：

- 锁对应的同产品活动进程仍存在时，以只读方式打开并显示并发写入说明；
- 锁进程不存在或锁心跳过期时，进入恢复扫描，允许在隔离副本中恢复最新稳定点；
- 不自动删除无法确认归属的正式锁文件；
- 保存重试只能针对当前项目身份和当前 session，不能把旧 session 的 revision 写入新画布。

正常退出等待当前草稿提交和稳定点落盘。保存失败时主进程显示取消退出、重试/返回画布或明确放弃未保存更改；默认动作必须保护数据。重新打开后必须恢复最后一次成功保存的项目、节点配置、连线和受管媒体。

### 4. CanvasForge Coexistence

Canvas Atelier 使用独立的 MCP 运行目录和运行文件，例如 `%APPDATA%\\Canvas Atelier\\mcp\\runtime-modern-v1.json`。客户端注册键继续使用独立的 `canvas_atelier`，不得覆盖 `canvasforge`。单实例锁依赖各自产品身份；两个程序同时启动时分别持有自己的项目锁和 MCP 运行时，不修改对方配置或状态。

## Installed Acceptance Matrix

### Video Node

- 空节点、输入中、素材已连接、生成中、成功结果、失败、停止后重试、折叠和展开状态逐一截图。
- 控制栏只有一层可见边框；五个参与者同一基线且完全位于节点内部。
- 模型能力决定比例、分辨率、时长和数量，不显示不受支持的组合。
- 连接的图片/视频素材按顺序持久化，关闭重开后端口和连线仍可见。
- 保存的 MP4 可点击播放；检查首段、中段和末段时间点，`readyState`、`currentTime`、`duration` 和媒体错误均记录。
- 不触发付费生成时，供应商真实生成结果明确标记为未执行，不能用模拟结果冒充。

### Image Generation Node

- 空节点、输入中、参考素材已连接、生成中、1 至 4 张结果、失败和重试状态逐一截图。
- 控制栏只有一层可见边框；模型、比例、清晰度、数量和生成按钮同一基线且不越界。
- 模型目录、参数变化、提示词和引用素材保存后重开完全一致。
- 生成结果与真实 asset id 绑定；发送到画布、复制和 Photoshop 入口分别验证成功或明确错误。
- 不触发付费生成时，真实供应商生成门禁单独标记为未执行。

### Reverse Agent Node

- 标题、模块库和工作台统一显示 `Agent 反推`，安装资源中不得出现 `反推anget`。
- 空素材、单素材、多素材、角色和任务输入、知识库选择、模型选择、运行中、成功、失败、中断后重试逐一验收。
- 输入素材顺序、角色、任务、知识库和模型路线保存重开后保持。
- Comfly、RelayMe 和 Codex 路线不得互相静默回退；没有兼容路线时显示明确原因。
- 结构化结果、错误分类、复制、编辑结果和再次运行均由安装版验证。

### Persistence And Exit

- 新建项目、编辑后自动保存、`Ctrl+S`、节点移动、连接、删除、撤销和重做均形成正确稳定点。
- 正常退出后重开、保存中立即退出、模拟写入失败、revision conflict、真实并发锁、陈旧锁和异常退出恢复分别验收。
- 最近项目必须指向原项目身份，不得静默创建空白替代项目。
- 所有错误结果记录脱敏错误码、可恢复动作和重开结果。

### Visual And Accessibility Coverage

- 亮色和暗色主题；1366x768、1440x900、1920x1080；支持的缩放级别。
- 每个接受的截图必须由本轮安装版生成并人工检查，不能使用旧截图或只读 DOM 值。
- 检查裁切、溢出、重叠、间距、字体、边框、圆角、焦点、键盘访问、控件标签和状态播报。
- 截图只能证明可见问题；键盘、语义、保存和媒体播放必须分别用交互与运行状态证明。

## Release Gates

1. 每个缺陷先增加会在当前 `1.6.90` 代码上失败的回归测试，再做最小实现并转绿。
2. 聚焦 Vitest、完整 Vitest、全工作区 typecheck、production build、完整 Playwright 和性能场景全部取得本轮新鲜结果。
3. 构建新的 Windows x64 NSIS 安装包，并记录版本、时间、大小、SHA-256、blockmap 和 `latest.yml`。
4. 把安装包装入独立验收目录，确认安装后 `app.asar` 与打包产物哈希一致。
5. 使用已安装 EXE 完成视频、生图、反推、保存/退出、旧项目副本和 CanvasForge 并行运行矩阵。
6. 三类节点分别输出通过/失败/未执行表。任何必需项失败、阻塞或仅有历史证据时，不得宣称正式验收通过，也不得交付为正式版。
7. 外部付费生成、Photoshop 活动文档或网络服务等需要额外授权/环境的项目必须单独列出，不能用配置存在或桥接可达替代真实成功。

## Deliverables

- 修复后的源码与防回归测试。
- 本轮安装版截图和脱敏机器可读验收结果。
- 视频节点、生图节点、反推节点三张独立验收表。
- 保存/退出/恢复与双软件共存验收表。
- 新的正式候选安装包及完整哈希信息。
- `docs/project-memory.md` 中记录本次根因、保护行为、验证命令、结果和残余风险。
