# GPT 辅助图片分层与 PSD：设计规格

日期：2026-09-23

状态：待用户审阅；尚未实施

适用基线：Canvas Atelier 1.6.155 源码候选

## 目标与现状

用户从一张画布图片的顶部工具栏进入「AI 分层」，先由视觉模型分析图片并得到可修改的图层方案，再由用户确认使用 GPT 图片模型逐层生成，最后在画布上得到可独立操作的图层节点、连线、合成预览及真正的多图层 PSD。颜色校正改为同一工具栏中的紧凑图标入口；原有校正能力与逐图参数不删除。明暗主题沿用当前 1.6.155 的紧凑视觉体系。

当前源码已具备手动 `image_layering` 节点、受管 RGBA 图层、隐藏/排序、合成预览、`ag-psd` 多图层导出及桌面 Photoshop 打开桥；自动拆层按钮因供应商协议未核实而禁用。此前 `2026-09-21-comfly-layered-psd-design.md` 假设 Comfly 提供专用 `seedream-v5-pro/layer-decomposition` 端点，其归属、请求和回包未获证明。本规格取代其中**自动分层供应商路径**，不覆盖或删除旧文件，也不把离线夹具等同于真实服务成功。

## 明确边界

- 生成图层的模型只能是当前已配置、目录能力和实际请求合同均支持图片编辑的 GPT Image 路线。分析可以使用用户选定的视觉分析模型；分析模型不得生成图层。
- 采用「理解原图 → 生成分层计划 → 逐层重绘」而非数学意义的无损拆解。GPT 可能改变产品细节、边缘、文字、Logo 或遮挡区域；界面必须明确提示，不能宣称像素级还原。
- 文字、Logo 和复杂标志仅作为透明**像素层**；首版不承诺 Photoshop 可编辑文字、矢量路径或精确 OCR。
- 原图作为不可变受管资产留在原图片节点。导出的 PSD 默认包含经验证的生成图层，不将原图偷偷混入合成或伪装成生成层。
- 首版要求一个背景层、至少一个且最多八个透明前景层。现有 PSD 编码器支持更多层，但自动生成上限先限制费用、耗时和画布密度。若分析建议超过八层，先要求用户在计划中合并/删减，不自动截断。
- 无法验证 Comfly 或其他代理对 GPT 透明图片编辑的真实支持时，在提交前阻断相应路线；不得退化为不透明图片抠图、切换到非 GPT 模型或把失败输出标为完成。

## 交互与信息结构

### 图片顶部工具栏

选中图片或悬停图片时，顶部工具栏显示两个同尺寸、低对比度的图标按钮：「AI 分层」（叠层图标）和「颜色校正」（调色板图标）。按钮有中文悬停提示、`aria-label`、键盘焦点和可见焦点环；禁用时说明原因。窄节点保留图标优先级，其他低频操作收进更多菜单，不能遮住图片或抢占拖动热区。

「颜色校正」打开现有逐图校正面板，仍可切换原图/自动/Nano Banana、手动参数、强度、前后对比和重置；只改变入口与面板密度，不改变已保存参数语义。颜色校正不影响 AI 分层所读取的原图像素：用户需要烘焙校正图时，必须先明确导出/转为新受管图片再分层，避免源与 PSD 颜色不一致。

### 分层对话框：分析阶段

对话框左侧展示当前原图，右侧显示分析模型、可用于分层的 GPT 图片模型、输出尺寸及状态。入口读取当前选中图片的**受管原始资产 ID**，不用页面临时 URL；多结果节点只读取用户当前选中的那一张。开始前提示「分析图片可能产生费用，尚不会生成图层」。分析按钮只提交一次视觉分析请求；超时、模型无视觉能力、账号不可用或返回结构无效时进入明确错误状态，不进入生成。

分析结果是可编辑计划：每层名称、类型（固定背景或透明前景）、从底到顶顺序、是否生成、简短内容说明及遮挡关系。用户可改名、调整顺序、关闭/合并建议层；背景不可关闭，前景至少保留一层。无文字的图像不凭空添加文字层。计划预览只画结构与说明，不用假透明图充当已经生成的图层。

### 确认阶段

「确认生成」前显示固定快照：原图、分析模型、精确 GPT 模型路由、输出尺寸、背景加前景的图层数、预计生成请求数（每层一次）和费用说明。价格未知时写「实际费用以供应商为准」，不编造金额。用户明确确认后才允许生成；改模型、尺寸、层数或原图会令既有确认失效，必须重新确认。不能因为分析完成自动开始付费生图。

生成按钮大小、层级与现有紧凑节点一致，不作为整张对话框最突出的巨型 CTA。分析、确认、取消及关闭均有加载/禁用状态和明确语义；弹窗支持 Escape、焦点约束与焦点返还。关闭弹窗不等于撤销已经送达供应商的收费任务。

## 分析与生成协议

分析输入为原图受管字节及尺寸、用户可选的分层意图；输出需经过结构化 schema 校验与本地规范化。模型输出是**建议**，不能直接视为可执行任务：拒绝重复层 ID、缺背景、空名称、非法顺序和超限层数。规范化后保留分析原文摘要以供用户查看，但任何 prompt 注入内容只作为图片数据和模型回复处理，不获得工具/文件/网络权限。

生成时对背景和每个透明层分别发起 GPT 图片编辑：每个请求都引用同一原图及已确认的层说明、层间关系、目标尺寸。背景提示要求补全被前景遮挡的区域；透明层提示要求只绘制该对象、背景透明，并用 PNG 或 WebP 交付。不得对透明层请求 JPEG。是否可并行由既有 provider 队列与并发限制决定，但每层始终有独立可追踪任务。不可把所有生成结果仅放进一个节点内的列表。

图片编辑请求走现有正式 provider bridge、凭据、`image_edit` 能力守卫、异步任务轮询及受管素材下载链。模型目录展示不等于真实 alpha 支持；生产提交前须确认选中路由能发送所需透明格式，返图后以像素实际校验。不接受供应商专用「分层」回包假设。已有 Comfly GPT 图片编辑的 `?async=true` 提交、task ID 及只读轮询规则继续适用；不新增盲目自动重试。

## 画布结果与数据模型

确认后保留原图片节点，在其旁边以紧凑布局创建一个「分层任务组」：背景节点、每个透明层节点、合成节点；原图与任务组有来源关系，所有图层分别连接到合成节点。图层节点显示名称、缩略图、状态、可见性和必要操作，合成节点显示按顺序的实时预览、重排入口及 PSD 导出。用户可展开、移动节点，连接和顺序对应实际合成；自动布局只放置新节点，不移动既有画布内容。当前单节点 `ImageLayeringWorkbench` 可作为合成节点的内部图层管理界面复用，但不能替代独立图层节点。

任务组保存稳定 `groupId`、`projectId`、`sourceNodeId`、`sourceAssetId`、`analysisId`、计划版本、精确模型路由与尺寸快照；每层保存 `layerId`、种类、顺序、可见性、受管资产 ID、宽高和任务 ID。节点/边身份稳定，不能因轮询或重开而重建重复节点。资产只保存受管 ID，不保存 blob/data/临时外部 URL。当前项目与节点归属校验沿用已有队列保护，外项目同名节点任务不得污染本组。

可见层状态为 `planned → queued → running → validating → completed`，失败为 `failed`，用户取消本地跟踪为 `cancelled` 或「供应商任务仍在运行」的明确状态。任务提交前先持久化与项目/图层绑定的 held job；提交后记录供应商 task ID。应用重启后只恢复查询已有 task ID 和已落盘受管资产，不重复付费提交；无确认或无法证明归属的中断任务 fail closed。修改图层顺序、可见性与节点位置按现有草稿/自动保存队列批量持久化，不因进度百分比每帧写 journal；终态资产落盘后作 durable checkpoint。显式保存必须 flush 草稿，关闭前等待已有 durable 边界，不吞掉保存错误或无限转圈。

「重试失败层」是一次新的付费生成：先展示该层、精确模型、尺寸和一次请求，再由用户明确确认；旧任务与资产保留为历史，不自动替换已成功的其他层。只读「重新加载结果」只查询任务/资产，不提交生成。取消若供应商不支持撤销，只停止本地后续调度并告知已提交请求可能继续计费。

## 质量门禁、预览与 PSD

每个返回文件先核对可解码媒体类型、受管落盘、实际宽高、像素预算及与计划尺寸的一致性。透明层必须有 alpha 通道且存在非平凡透明/非透明区域；全不透明、全透明、边界严重裁切或来源不明的文件标为「需检查/失败」，不能冒充有效图层。背景必须覆盖整幅画布且基本不透明；遮挡补全、文字准确性和边缘质量属于人工复核项，界面提供原图/合成对比，不声称算法能自动证明视觉一致。质量告警保留已经成功的层和原图。

合成按底到顶顺序 alpha compositing；可见性和重排即时反映到预览、保存结果与导出。仅当背景及所有**已纳入计划**的透明层都有效、尺寸一致且合成成功时，标记「可导出完整 PSD」。未完成或结构不合格时禁用完整 PSD 出口并说明具体层；不把部分层合成为「已完成」。导出复用现有 `ag-psd` 路径，产生 8-bit RGB PSD，独立 RGBA 像素层、名称、顺序、可见性、位置及合成预览；导出后做 PSD readback/像素抽样回归。桌面 Photoshop 桥仍写入真正的 PSD 文件后打开，而不是展平单图智能对象。实际 Photoshop 兼容性单列实机验收。

## 安全、性能与失败体验

- 图片和模型回复只进入受控解析与受管素材存储；不把模型分析文本执行为代码，不把供应商原始错误或凭据显示在界面。
- 原图、成功层和失败原因在分析失败、生成失败、保存失败、项目重开后保留。修复动作清楚区分「只读重载」「重新分析」「新付费重试」。
- 新任务组在画布低缩放时沿用轻量节点壳和原生可见性裁剪；缩略图 lazy decode，预览只在展开/可见时合成，避免多个 4K RGBA 同时主线程解码拖慢拖动和输入。
- 长任务不得锁死整个画布；保存与任务轮询解耦，避免供应商慢请求导致保存按钮无限转圈。发生 revision conflict 时显示可恢复错误，不以旧响应覆盖新项目。
- 明暗主题检查图标按钮、禁用态、弹窗、任务进度、错误提示、连线和合成预览；可用键盘完成分析、改计划、确认、隐藏/排序与导出。

## 验收与证据层级

1. **源码单元/集成**：分析 schema、计划编辑与确认快照、仅 GPT 生成路线、透明请求格式、提交一次/轮询多次、跨项目任务归属、失败层重试确认、受管资产、alpha/尺寸门禁、合成和 PSD readback。关键 bug 先写失败用例再修复。
2. **本地浏览器 E2E**：图片工具栏两图标、深浅色和键盘、分析→改计划→确认、独立节点/连线、进度、层隐藏/排序、PSD 下载、快速图槽换位后保存/重开、失败和只读重载。使用隔离项目和零费用 fixture，不触碰真实项目。
3. **画布性能**：对当前 300 节点/500 连线压力场景及多层 2K/4K 合成测拖动、缩放、输入响应与保存时延；记录硬件、样本、P95 和最长停顿，失败则优化，不把单次通过概括为所有机器流畅。
4. **候选/安装版**：重新 build/package，对精确 `app.asar`、renderer 和安装目录哈希校验，在安装版隔离项目复跑节点、PSD、保存/重启及明暗 UI。源码通过不等于安装版通过。
5. **外部边界**：真实 Comfly GPT 编辑、真实透明 alpha、计费/异步任务与真实 Photoshop 打开必须独立记录；未获得针对模型、尺寸、预计请求数的明确付费确认前不发起真实生成。无供应商协议或账号实测时标「未验证/阻断」，不伪造 PASS。

## 实施顺序与待审决策

实施计划需在本规格获用户审阅后另写：先锁定数据/任务合同与红测，再做分析和确认，接入逐层 GPT 编辑，落盘图层/画布图，最后收紧 UI、性能及安装版验收。不得把本设计稿视为已实现。

请用户重点确认两项产品取舍：首版自动层数上限为「背景 + 最多八个透明层」；PSD 默认不附带隐藏原图参考层（原图仍在画布中保留）。若需调整，应在实施计划前修改本规格。
