# CanvasForge MCP 工作流桥接设计

## 目标

为 Windows 桌面版 CanvasForge 提供真实可运行的 MCP 服务，使 Codex 和 WorkBuddy 能读取当前画布节点能力、理解端口与限制、根据用户工作内容生成工作流计划，并在用户确认与权限允许后创建节点、连接端口和执行任务。

## 当前问题

- 设置页“连接 WorkBuddy”按钮没有执行逻辑。
- 当前“复制 MCP 配置”只包含节点说明，不包含可启动服务的 `command`、`args` 或可连接的 `url`。
- WorkBuddy 本机旧配置指向 `D:\CanvasForge`，不是当前构建或安装路径。
- 项目已经有 `canvasforge.mcp.workflow.v1` 节点合约，但没有 MCP transport、工具注册、请求处理或运行时连接。
- 设置页显示固定“未连接”，不会读取真实客户端或服务状态。

## 总体架构

### 内置 stdio 桥接

- 桌面安装包携带独立的 Node/Electron-as-Node stdio MCP 入口。
- Codex 和 WorkBuddy 分别启动自己的 stdio 桥接进程。
- stdio 进程通过桌面应用生成的运行时描述文件发现当前 CanvasForge 实例。
- 运行时描述文件只保存本机端点、实例标识、协议版本和短期认证信息，不保存模型密钥。
- 桌面应用重启后更新运行时描述，客户端桥接自动重新发现。
- 不依赖固定 TCP 端口。

### 画布运行时服务

- 桌面主进程持有唯一画布写权限。
- MCP 桥接只能调用严格定义的工具，不接受任意 IPC、脚本或文件路径。
- 所有写操作转换为现有项目事务并进入撤销栈、持久化队列和恢复日志。
- MCP 写操作与用户界面操作共享同一项目版本与冲突检查。

## MCP 工具

### 读取

- `canvas_describe_nodes`：返回节点类型、名称、用途、端口、数据类型、限制和推荐下游节点。
- `canvas_read_workflow`：返回当前画布节点、连线、位置、公开配置和运行状态。
- `canvas_get_selection`：返回当前用户选中的节点与连线。
- `canvas_get_job_status`：返回反推、生图、视频任务状态和受管结果标识。

### 规划

- `canvas_plan_workflow`：根据用户工作内容生成节点、连线和配置计划，不直接修改画布。
- 计划必须通过现有节点合约验证端口方向、数据类型、基数和必填项。
- 返回可读摘要、预计创建内容、需要确认的付费任务和不能满足的限制。

### 写入

- `canvas_apply_workflow`：使用用户确认令牌一次性应用已验证计划。
- `canvas_create_node`：创建一个受支持节点。
- `canvas_update_node`：更新白名单配置字段。
- `canvas_connect_nodes`：连接兼容端口并保持输入顺序。
- `canvas_move_nodes`：移动指定节点。
- `canvas_delete_selection`：仅在删除权限和二次确认同时存在时删除选中内容。

### 执行

- `canvas_run_node`：运行反推、图片生成或视频生成节点。
- 付费或外部模型任务必须返回确认请求，不能因一次自然语言消息自动扣费。
- `canvas_cancel_job`：取消当前运行任务。
- `canvas_import_media`：仅在外部文件访问权限开启并由用户明确选择文件后导入。

## 权限与确认

- 默认允许读取画布、编辑画布、管理普通节点和导出受管结果。
- 默认关闭危险操作、任意外部文件访问和未确认删除。
- AI 生成权限允许工具提出任务，但执行仍需要用户确认。
- 权限变化由设置页保存，并立即影响新工具调用。
- MCP 不返回 API 密钥、认证头、绝对素材路径、base64 原图或知识库私有文件内容。

## Codex 与 WorkBuddy 配置

### WorkBuddy

- “连接 WorkBuddy”先读取现有 MCP 配置并创建带时间戳备份。
- 只新增或更新 `canvasforge` 条目，保留 connector-proxy、Figma 和其他服务器。
- 配置使用当前安装路径生成 `command` 与 `args`，不写死 `D:\CanvasForge`。
- 写入完成后执行一次 MCP 初始化与工具列表自检。

### Codex

- 设置页提供“连接 Codex”和“复制 Codex 配置”。
- 自动配置前展示将写入的服务器名称、命令和权限摘要。
- 只新增或更新 CanvasForge MCP 条目，不覆盖其他 Codex 配置。
- 连接后通过工具列表和 `canvas_describe_nodes` 做健康检查。

## 设置界面

- 显示 MCP 服务状态：未启动、运行中、等待画布、错误。
- 分别显示 Codex 与 WorkBuddy：未配置、已配置、已连接、连接失败。
- 显示服务版本、协议版本、最近心跳和已注册工具数量。
- 提供“连接 WorkBuddy”“连接 Codex”“复制配置”“测试连接”“断开”。
- 显示真实错误原因和修复操作，不能长期固定显示“未连接”。
- 高级诊断显示运行时文件、客户端发现和恢复状态，但不显示认证信息。

## 工作流行为

1. 用户在 Codex 或 WorkBuddy 输入工作内容。
2. Agent 调用 `canvas_describe_nodes` 理解可用能力。
3. Agent 调用 `canvas_read_workflow` 读取当前状态。
4. Agent 调用 `canvas_plan_workflow` 生成计划。
5. CanvasForge 在画布内显示计划预览。
6. 用户确认后，Agent 使用确认令牌调用 `canvas_apply_workflow`。
7. 节点和连线写入画布；付费任务再次单独确认后才能执行。

## 错误与恢复

- CanvasForge 未运行：桥接返回可重试的“等待画布”状态。
- 运行时描述过期：重新发现当前实例，不使用旧端点继续写入。
- 项目版本冲突：拒绝写入并要求 Agent 重新读取画布。
- 不兼容端口或未知节点：拒绝计划或连接并返回具体字段错误。
- 客户端配置失败：恢复备份，不留下半写配置。
- 工具调用中断：项目事务要么完整提交，要么不提交。

## 测试与验收

- 协议测试：初始化、工具列表、工具调用和错误响应。
- 合约测试：所有真实画布节点均可描述，端口与运行时定义一致。
- 安全测试：不泄漏密钥、路径、base64 或知识库私有内容。
- 事务测试：创建、连接、移动和删除均可撤销并持久化。
- WorkBuddy 集成测试：配置备份、合并、启动、工具列表和工作流应用。
- Codex 集成测试：配置合并、启动、工具列表、读取画布和应用计划。
- 手动验收：用户分别从 Codex 和 WorkBuddy发送工作内容，看到同一画布计划，确认后生成正确节点与连线。

## 非目标

- 不允许 Agent 绕过确认直接运行付费任务。
- 不允许 MCP 执行任意 shell 命令或读取任意本地文件。
- 不覆盖其他 MCP 服务器配置。
- 不依赖旧 `D:\CanvasForge` 安装路径。
- 不把设置页的静态节点说明冒充可运行 MCP 配置。
