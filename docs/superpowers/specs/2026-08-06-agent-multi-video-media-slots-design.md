# Agent 多视频素材图槽设计

## 目标

让画布中的 Agent 对话与 Agent 反推使用同一套有序素材图槽。用户可连接或添加图片与受管 MP4 视频，合计最多 20 个，并可在图槽中自由拖动换位。保存项目、重新打开项目、跨设备同步与模型执行都必须保持同一顺序。

## 已确认规则

- Agent 对话和 Agent 反推都支持图片与视频混合输入。
- 每个 Agent 节点最多 20 个素材，图片与视频合计计数，不分别扩容。
- 支持多个 MP4 视频，不再限制为单个 `videoInput`。
- 图槽显示每个素材的缩略图或视频封面、媒体类型和顺序编号。
- 用户可把任意图槽拖到任意位置；拖动结束后其他素材自动让位。
- 删除素材后剩余序号连续重排。
- 模型收到的多模态输入顺序必须与界面图槽顺序完全一致。
- 超过 20 个时在界面阻止添加，并返回明确错误；不得静默截断或丢弃视频。
- 只允许项目受管媒体，不传递任意本地路径或外部 URL。

## 方案比较

### 方案 A：统一有序媒体数组（采用）

把图片和视频统一表示为 `orderedMedia[]`，每项包含 `kind`、`assetId`、完整性身份和顺序。Agent 对话、Agent 反推、持久化、桌面桥接和 Provider 都消费这一数组。

优点：顺序只有一个事实来源；多视频、拖动换位和跨设备恢复自然一致；不会出现图片数组与单视频字段互相错位。缺点：需要迁移旧的 `references + videoInput` 合同。

### 方案 B：保留图片数组并增加视频数组

分别保存 `referenceAssetIds[]` 与 `videoAssetIds[]`，再额外维护混合顺序表。

优点：对旧接口改动较小。缺点：存在三份顺序状态，容易在拖动、删除和恢复项目时不同步，不采用。

### 方案 C：每个视频独立子节点执行

每个视频分别运行反推，最后合并文本结果。

优点：能绕开部分模型单请求限制。缺点：改变用户期望的整体多模态分析语义，成本和延迟更高，不采用。

## 数据合同

新增统一媒体项：

```ts
interface OrderedAgentMediaItem {
  readonly kind: 'image' | 'video';
  readonly assetId: string;
  readonly sha256: string;
  readonly byteSize: number;
  readonly mediaType: 'image/gif' | 'image/jpeg' | 'image/png' | 'image/webp' | 'video/mp4';
  readonly order: number;
}
```

Agent 运行请求使用：

```ts
interface AgentMultimodalRunInput {
  readonly orderedMedia: readonly OrderedAgentMediaItem[];
}
```

约束：

- `orderedMedia.length` 为 1–20。
- `order` 必须从 0 连续递增且不可重复。
- `assetId` 不可重复。
- 每个视频仍需通过现有 MP4 格式、尺寸、时长与单文件大小验证。
- Provider 若不支持多个视频，必须在模型选择或执行前显示能力错误，不得只发送第一个视频。

旧项目迁移：把旧图片引用按原顺序写入数组，再把旧单个视频放在其原连接顺序位置；无法取得旧顺序时放在图片之后，并只迁移一次。

## 连接与顺序

画布边的 `order` 是连接顺序的持久化来源。图槽拖拽完成后，通过一个原子事务更新该 Agent 节点所有入边的 `order`：

1. 读取当前 Agent 的有效图片/视频入边。
2. 按拖拽结果生成完整的新边顺序。
3. 一次事务提交全部边，避免中间重复序号。
4. 更新 UI 后立即校验 0–N-1 连续顺序。
5. 保存项目和跨设备同步沿用更新后的边顺序。

Agent 对话中直接添加的素材如果暂时没有独立输入节点，则先创建受管输入节点与连接边，再进入相同的排序流程，避免出现仅存在于聊天组件本地状态的素材。

## UI

Agent 对话与 Agent 反推共用 `ConnectedMediaSlots` 组件及同一套尺寸、间距和主题变量。

- 浅色、深色主题布局一致，只切换设计令牌。
- 每个图槽显示封面；无法提取视频封面时使用统一视频占位图标，但仍显示文件名与序号。
- 拖动时原位置保留占位，目标位置显示插入指示线。
- 整个缩略图可拖动；删除按钮与预览按钮不会触发节点拖动。
- 键盘提供“前移/后移”操作，保证无法拖拽的用户也能换位。
- 计数统一显示 `已连接素材 N / 20`。
- 第 20 个素材后禁用添加入口并显示“最多 20 个图片或视频素材”。

## `@` 图片引用

Agent 对话、Agent 反推任务、生图提示词和视频提示词统一支持在光标位置输入 `@` 打开图片引用小窗。

- 小窗只列出项目受管图片，按最近使用和项目顺序显示，最多展示 20 个候选并支持继续搜索。
- 每项显示真实缩略图、图片名称和短引用编号，例如“图片 1  @1”。
- 选择后在文本光标位置插入 `@1`，同时在输入框附近显示带缩略图的引用小卡。
- 文本标记只用于编辑显示；请求使用独立的 `citations[]` 保存 `token`、`assetId` 和 `label`，不能靠文件名反解析资产。
- 删除文本中的完整引用标记或点击引用小卡的删除按钮时，同步移除对应 citation。
- 重复选择同一图片时聚焦已有引用，不重复发送同一资产。
- 发送前验证引用图片仍是可用的项目受管资产；缺失时指出具体 `@N` 并阻止执行。
- Agent 对话、Agent 反推、生图和视频生成都必须把 citations 对应的图片加入本次请求；不得只插入可见文字而不传图片。
- `@` 图片引用与节点图槽可以指向同一资产，但执行时按 assetId 去重；图槽顺序优先，只有文字引用的图片按 `@1`、`@2` 顺序追加。
- 默认不显示单独的 `@` 按钮；只有用户输入 `@` 时才弹出小窗，符合现有对话栏规范。

统一引用结构：

```ts
interface ImageCitation {
  readonly token: `@${number}`;
  readonly assetId: string;
  readonly label: string;
}
```

UI 在浅色与深色主题中使用同一尺寸和间距。菜单采用紧凑浮层，不遮住发送按钮、模型选择和知识库选择；素材过多时内部滚动，不扩大 Agent 面板。
## 执行数据流

1. 用户把图片或多个视频连接到 Agent，或从 Agent 对话图槽添加项目素材。
2. 图槽根据入边 `order` 渲染混合媒体。
3. 用户拖拽换位，画布以原子事务更新边顺序。
4. 执行前重新从当前项目解析媒体，验证数量、类型、完整性与模型能力。
5. Desktop bridge 按 `orderedMedia` 顺序读取受管文件内容。
6. Provider adapter 按同一顺序组装多模态消息，不重新分组图片和视频。
7. 运行快照保存媒体身份和顺序，历史结果可准确复现输入。

## 错误处理

- 第 21 个素材：阻止添加，保留原 20 个。
- 重复素材：不重复添加，并聚焦已有图槽。
- 资产缺失或完整性失败：阻止执行并指出具体序号。
- 非 MP4 或视频超限：阻止添加/执行并显示原因。
- 当前模型不支持多视频：在模型选择和运行按钮附近显示能力提示，禁止执行。
- 拖拽中断：不提交事务，保持原顺序。
- 保存失败：恢复原边顺序并显示可重试错误。

## 测试与验收

- Domain：接受 20 个图片/视频混合媒体，拒绝第 21 个、重复 ID、非连续顺序和非法媒体。
- Renderer resolver：解析多个视频及图片并保持边顺序，不再返回单个 `videoInput`。
- Store：拖拽换位一次事务更新全部入边；取消、保存失败保持旧顺序。
- Agent 对话与反推组件：共同显示多个视频封面，支持鼠标拖拽和键盘前移/后移。
- @ 引用组件：四个输入位置都在键入 `@` 时显示缩略图菜单，选择后创建 `@N` citation 并把真实图片加入请求。
- Desktop bridge：按顺序读取多个受管视频并拒绝身份不匹配。
- Provider：构建交错的图片/视频内容顺序；不静默丢弃第二个视频。
- E2E：浅色和深色各验证至少 2 个视频 + 2 张图片连接、拖拽换位、刷新后顺序保持、运行前请求快照顺序一致；并验证 Agent 对话、反推、生图和视频提示词的 `@` 图片引用菜单与请求资产。
- 截图：输出浅色与深色 Agent 对话、Agent 反推图槽截图，以及 MCP、API 与模型、存储与备份设置截图。

## 非目标

- 不允许任意网络视频 URL。
- 不在本轮加入视频剪辑、抽帧编辑或时间轴裁切界面。
- 不在自动化验证中调用付费模型。
- 不打包安装程序，直到用户完成页面检查。
